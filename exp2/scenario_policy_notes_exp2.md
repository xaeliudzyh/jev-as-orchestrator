# Сценарная политика exp2: обоснование

Версия от 09.11.2026. Политика добавлена в
[RU](prompts/routing_scenarios_ru_exp2.txt) и [EN](prompts/routing_scenarios_en_exp2.txt).
Обе версии описывают одинаковое правило выбора владельца маршрута.
Исходные descriptions, полные тексты агентов и эталоны сохранены.

## Что проверено

Корзина: 193 вопроса, 17 включённых кандидатов. Проанализированы четыре запуска
из `experiments/exp2/1-step/`:

| Модель | RU, прежняя краткая инструкция | EN, прежняя общая инструкция |
| --- | --- | --- |
| Jev 1.14 | `typesafe__jev-1.14_20261109T110750.875574+0300` | `typesafe__jev-1.14_20261109T112426.913512+0300` |
| Luna Decisions | `openai__gpt-6-luna-decisions_20261109T110934.530535+0300` | `openai__gpt-6-luna-decisions_20261109T112628.542481+0300` |

Подробные исходные ошибки и матрицы:
[analysis/confusion_last4_20261109](../experiments/exp2/analysis/confusion_last4_20261109/README.md).
Последний Jev ошибается по top-1 на 74/193, последняя Luna — на 87/193,
включая один отказ API. Настройка промпта не исправляет транспортные отказы.

## Причины и признаки для выбора эталонного маршрута

| Сценарий | Почему ошибается модель | Правило/признаки нового промпта |
| --- | --- | --- |
| 30 обычных HR-ссылок → hrp-analytics | Description service_navigation прямо перечисляет эти порталы; все четыре запуска промахиваются | Стандартные HR-точки входа принадлежат HRP по принятой политике, несмотря на пересечение description |
| 5 запросов вовлечённости → HRP | Description metrics почти дословно совпадает с вопросами; все четыре промахиваются | eNPS, Пульс, комментарии и динамика вовлечённости → HRP |
| 3 создания встреч → HRP | meetings явно заявляет создание; все четыре промахиваются | Новая встреча → HRP; перенос/редактирование/отмена и свободные слоты остаются meetings |
| 7 переработок/РВД → vacation | В description vacation есть только отпуска, поэтому запросы уходят в HRP; все четыре промахиваются | РВД, выходные, нерабочие дни, часы/количества переработок явно закреплены за vacation |
| Сводка по заштатным → HRP | outstaff явно тематический специалист | Агрегат и влияние на банк → HRP; иные специальные запросы по упразднённым должностям — по outstaff description |
| Командные теги, хобби, Python/ML → team_profile | Слова «сколько/топ/блок» включают широкий HRP; короткое описание team_profile сужает scope | Объект — интерес/профессиональный тег; масштаб блока/трайба и агрегация не меняют владельца. Полный AGENTS.md действительно содержит этот scope |
| Формальные AI-навыки → agentic_skills | Численность и распределения принимаются за общий HR-запрос | Компетенции n1–n6, GigaCode, доля AI-кода, prompting и поиск по AI-уровню важнее формы «сколько» |
| Профиль с оценкой пригодности/360 → ai-coach | Обычный «профиль сотрудника», командный отчёт или рейтинг ведёт в HRP | Отличать развивающую оценку конкретного человека и специализированный 360 от обычной биографии и квартальной/годовой эффективности |
| Общая диагностика hard+soft+360 → HRP | Одно упоминание 360 уводит в ai-coach | Центральная задача — комплексная картина команды; в узком отчёте только по 360 владелец ai-coach |
| Завершение/назначения обучения → education | Нет слова «просрочка», а description его подчёркивает | Статус курса, завершение, обязательные назначения, сроки и обученность достаточно специфичны |
| Учебные статьи/материалы СберУниверситета → mcp_internet | Ограничение «внешние» и слово «внутренний» ведут в навигацию | По принятой политике поиск образовательных ресурсов включает книги/статьи и университет; назначенное обучение остаётся education, ссылка на HR-раздел — HRP |
| Внешний поиск руководителей → talent-research | Ключевые слова «позиция/кандидат» ведут в recruiter | Внешний рынок, executive sourcing, замена/усиление внешним наймом. Поиск нового руководителя по профилю без внутренних/вакансионных операций — явный default |
| Новые преемники/ротация → top600-successor-rotation | Путаются поиск кандидатов, факт об уже назначенном преемнике и внешний рекрутинг | Действие «подобрать/номинировать/резерв» → top600; существующий преемник/покрытие → HRP; внешние-only → talent-research; смешанный внутренний/внешний поиск руководителя → top600 |
| Сервисная адаптация новичка → onboarding_top_600 | Слова ДМС/развитие ведут в навигацию/коучинг | Контекст новичка, доступы/привилегии, семейное ДМС, лимиты поездок, контакты помощи → onboarding; сами развивающие цели → ai-coach |
| Неопределённый результат → grill | Название темы воспринимается как достаточный запрос аналитики | Если отсутствует действие/результат, grill выше тематического правила; недостающий параметр при ясном действии уточнит профильный агент |

Сценарные правила нужны именно потому, что часть эталонов нельзя вывести только
из описаний. Это сознательные исключения текущего развёртывания, а не найденные
в AGENTS.md дополнительные возможности. Они имеют одинаковый приоритет на
первом и втором этапе, поэтому полный текст не должен отменять владельца маршрута.
Остальные сценарии по-прежнему выбираются по каталогу; кандидаты без эталонных
примеров не отключаются и не исключаются из распределения.

## Неоднозначности и пределы

Часть запросов недоопределена: «мои оценки» не указывает вид оценки,
«пересечения в команде» — отпуска, а вопрос о помощи с целями развития — контекст
новичка ТОП-600. В политике заданы ограниченные значения по умолчанию для таких
формулировок. Есть и повреждённый запрос про разработчиков, где после «уровня»
пропущено значение и нет явного AI-контекста; универсально восстановить намерение
из state.query нельзя. Не добавлялась таблица точных вопросов с правильными ответами.

Полные тексты могут ограничивать доступ, например к чужим индивидуальным оценкам.
Промпт выбирает владельца, но не отменяет эти ограничения: выбранный субагент
сам проверяет доступ и выполнимость. Делегирование не означает, что операция
разрешена или гарантированно поддерживается. Model input не содержит gold,
sample_id, skill_name или скрытый контекст пользователя.

Политика измерена на Jev/Luna: последние сценарные прогоны дают 91–94% top-1.
[Аудит метрик и переноса](../experiments/exp2/analysis/prompt_generalization_20261109/README.md)
показывает спорные gold-попадания и существенную подгонку правил по эталонам.
Поскольку эти 193 вопроса использованы для выбора правил, результат относится
к данным разработки. Общие варианты без фиксированных маршрутов:
[routing_general_ru_exp2.txt](prompts/routing_general_ru_exp2.txt) и
[routing_general_en_exp2.txt](prompts/routing_general_en_exp2.txt). Для оценки
переноса нужен отдельный набор, особенно с похожими, но разными намерениями:
профиль/пригодность, существующий/новый преемник, ссылка/материалы/назначения,
командные теги/общая HR-аналитика, создание/изменение встречи.
