## Что заморожено

- bucket_full.csv/jsonl — исходные 193 вопроса; CSV побайтово совпадает с корзиной на момент разбиения.
- bucket_train.csv/jsonl и bucket_test.csv/jsonl — исходные три колонки, исходный порядок строк внутри каждой части.
- manifest.json — SHA-256 входов/экспортов, квоты, исходные sample_id, их отображение на индексы файлов train/test. Исходные sample_id с нуля, как у раннера.
- catalog_enabled.jsonl — статический каталог всех 17 включённых агентов.
- author_train_input.json — только 135 query/target_subagent и каталог. train_id перенумерован 0..134; исходные индексы, test, skill_name и история экспериментов не включены.

Разбиение: test=ceil(N*0.30); начальные квоты floor(0.30*N_label)
с ограничением 1<=N_test_label<=N_label-1; остаток выдаётся по наибольшему
недобору от квоты, алфавитный порядок разрешает равенства. Seed=42 выбран
однократно до авторства промпта, без поиска по метрикам. Внутри метки
SHA-256(JSON[seed,label,original_sample_id,query]) задаёт порядок отбора в test.
Нормализованные точные дубликаты запрещены; семантически похожие запросы
в отдельные группы не объединялись.

## Авторство промпта

Задание и технический протокол находятся в
[train70_prompt_build_20261111](../../../../experiments/exp2/analysis/train70_prompt_build_20261111/).
Автору предназначен только author_train_input.json, без manifest/test/старых
промптов/результатов. Для статического каталога разрешены descriptions и полные
AGENTS.md, которые доступны моделям при обычном инференсе.

Авторство успешно завершено после явного согласия пользователя на передачу
train+каталога в OpenAI. Отдельный ephemeral Codex CLI получил полный разрешённый
вход через stdin, без истории этого чата. Landlock запретил чтение репозитория,
test и старого промпта; успешный trace подтверждает ноль вызовов инструментов.
Промпт сохранён без содержательных изменений в exp2/prompts/routing_train70_ru_exp2.txt.
Хеши и происхождение — в prompt_freeze.json и author_protocol.json.
Jev/Luna-прогоны не запускались: пользователь получает команды для оценки.

## Оценка

После фиксации нового промпта достаточно полного прогона по bucket_full.csv
на каждой модели. exp2/evaluate_holdout_exp2.py извлечёт full/train/test метрики
из тех же сохранённых ответов, без повторных API-вызовов. Команды — в exp2/README.md.
Индекс sample_id в отдельно запущенном bucket_test.csv локальный и отличается
от исходного: evaluator полного прогона использует mapping из manifest.json.

Главный показатель обобщения — test@1/3/5, без порогов confidence, подобранных
по прежним 193 вопросам. Full содержит train и не является независимым test.
Старый сценарный промпт настраивался по всем 193: сравнение с ним описательное,
его результат на этих 58 нельзя считать честной holdout-оценкой.
Один test-промах меняет accuracy на 1/58=1.72 п.п. В редких классах test=1,
поэтому class-level оценки крайне нестабильны. Это внутридатасетное разбиение,
а не проверка на новых типах задач/временном production-срезе. После правок
промпта по test этот test становится dev-набором.
